# 排错案例与讲解提纲

## 两分钟讲解草稿

我为理解ERP进销存业务，在指导下完成了一个文具店SQL模拟项目。使用MySQL和DBeaver，围绕4种商品建立5张关联表，记录采购入库、销售出库和两类退货。

报表先分别汇总四类数量，再关联商品档案。这样可以避免入库和出库明细直接关联后重复计数。以商品为主表做左关联，还能保留没有交易的商品。最终中性笔库存为95支，笔记本为20本，另外两种商品为0。

我还练习了按照原出库记录汇总客户退货，找出累计退货超过出库的情况，区分正常退货、全部退回、超量和未退货。项目是个人模拟练习，没有接入企业ERP；我目前的重点是解释数据关联和核对逻辑，不把它当成上线经验。

请用自己的语言复述，不要求逐字背诵。无法解释的SQL可以如实说明是在指导下完成、还在巩固。

## 案例一 库存107与105的差异

发生在加入供应商退货之前。中性笔应为150−50+5=105，查询却显示107。检查客户退货明细，发现多了一笔关联出库编号2、数量2的误录退货。确认错误记录后进行定点纠正，再查询回到105。

这不是少算出库，而是多记客户退货。不能只修改报表结果凑成105，也不能只编辑脚本文字就认为数据库记录已改变。原练习中的DELETE保留在个人原文件里，整理版初始化不包含该误录记录，也不自动执行删除。企业环境需遵守权限、审批、备份和审计要求，不能照搬练习中的删除操作。

加入供应商退货10支后，正确结果进一步变成95，不是又出现了错误。

## 案例二 入库150为何变成300

中性笔有2笔入库100和50、2笔出库30和20。按商品直接关联明细，产生4对组合，两个入库数各出现2次，因此入库求和300；出库求和也变成100。应先分别按商品汇总，再关联一行对一行。不能依靠SUM(DISTINCT quantity)，因为不同业务记录可能恰好数量相同，去重会丢失真实数量。

## 自测问题

1. 为什么退货表关联原出库编号，而不是只存商品名？答：可追溯原记录，也能按单检查累计退货数量。
2. 为什么LEFT JOIN不能随便改成INNER JOIN？答：无交易商品会丢失；只在某侧有交易的商品也可能丢失。
3. COALESCE解决什么问题？答：无匹配汇总时NULL转为0，使无交易商品仍能计算库存。
4. WHERE与HAVING的区别？答：前者过滤参与汇总的明细，后者过滤汇总后的分组。
5. 查询能阻止退货超量吗？答：不能，目前仅事后检测；事务和并发安全的写入校验尚未实现。
6. 新增一笔中性笔正常出库10支，其他不变，库存应为多少？答：85支。先口算，再解释哪一个汇总改变，不必修改当前验收数据。
